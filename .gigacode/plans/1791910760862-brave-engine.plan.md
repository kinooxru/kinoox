# План: Docker Worker для синхронизации каталога

## Контекст

Фоновые задачи синхронизации (VeoVeo + Vibix) запущены в процессе API через `setTimeout`/`setInterval`. Выносим в отдельный Docker-сервис.

Внешние cron-сервисы не подходят (Vercel Free без cron, cron-job.org тормозит). Docker Worker на своём сервере — лучший вариант.

## Решение

Создать standalone воркер в отдельном Docker-контейнере:
1. `apps/api/src/worker.ts` — entry point для воркера
2. `apps/api/Dockerfile.worker` — Dockerfile для воркера
3. Добавить сервис `worker` в `docker-compose.yml`
4. Удалить таймеры из `server.ts`
5. Обновить `deploy.sh`

## Изменения

### 1. `apps/api/src/worker.ts`

```typescript
/**
 * Worker — standalone процесс для фоновой синхронизации каталога.
 * Запускает CatalogSyncService с таймерами:
 * - syncOngoingTitles() — каждый час
 * - importLatestFromBalancers() — каждые 2 часа
 */
import { PrismaClient } from '@prisma/client'
import { CatalogSyncService } from './modules/sync/catalog.sync.service'
import { config } from './config'
import pino from 'pino'

const logger = pino({
  level: 'info',
  transport: config.isDevelopment
    ? { target: 'pino-pretty' }
    : undefined,
})

async function main(): Promise<void> {
  const prisma = new PrismaClient()
  const syncService = new CatalogSyncService(prisma, null)

  logger.info('Worker запущен')

  // Initial sync after 5s
  setTimeout(async () => {
    logger.info('Запуск initial sync онгоингов...')
    try {
      const results = await syncService.syncOngoingTitles()
      logger.info({ count: results.length }, 'Initial sync онгоингов завершён')
    } catch (err) {
      logger.error({ err }, 'Ошибка initial sync онгоингов')
    }
  }, 5000)

  // Periodic ongoing sync — каждый час
  setInterval(async () => {
    logger.info('Запуск periodic sync онгоингов...')
    try {
      const results = await syncService.syncOngoingTitles()
      logger.info({ count: results.length }, 'Periodic sync онгоингов завершён')
    } catch (err) {
      logger.error({ err }, 'Ошибка periodic sync онгоингов')
    }
  }, 60 * 60 * 1000)

  // Periodic latest import — каждые 2 часа
  setTimeout(() => {
    setInterval(async () => {
      logger.info('Запуск periodic import новинок...')
      try {
        const result = await syncService.importLatestFromBalancers({
          veoveoPages: 2,
          vibixLimit: 40,
        })
        logger.info({ imported: result.imported }, 'Periodic import новинок завершён')
      } catch (err) {
        logger.error({ err }, 'Ошибка periodic import новинок')
      }
    }, 2 * 60 * 60 * 1000)

    // Initial import after 10s
    setTimeout(async () => {
      logger.info('Запуск initial import новинок...')
      try {
        const result = await syncService.importLatestFromBalancers({
          veoveoPages: 2,
          vibixLimit: 40,
        })
        logger.info({ imported: result.imported }, 'Initial import новинок завершён')
      } catch (err) {
        logger.error({ err }, 'Ошибка initial import новинок')
      }
    }, 10000)
  }, 0)

  // Graceful shutdown
  const shutdown = async (signal: string): Promise<void> => {
    logger.info({ signal }, 'Получен сигнал завершения — останавливаю воркер')
    await prisma.$disconnect()
    logger.info('Воркер остановлен')
    process.exit(0)
  }

  process.on('SIGTERM', () => void shutdown('SIGTERM'))
  process.on('SIGINT', () => void shutdown('SIGINT'))
}

main().catch((err) => {
  console.error('Failed to start worker:', err)
  process.exit(1)
})
```

### 2. `apps/api/Dockerfile.worker`

```dockerfile
# ── Этап 1: зависимости ──────────────────────────────────────
FROM node:20-bookworm-slim AS deps

ENV PNPM_HOME="/pnpm"
ENV PATH="$PNPM_HOME:$PATH"
RUN corepack enable

WORKDIR /repo

COPY pnpm-workspace.yaml package.json pnpm-lock.yaml* ./
COPY apps/api/package.json apps/api/package.json
COPY packages/api-client/package.json packages/api-client/package.json
COPY packages/design-system/package.json packages/design-system/package.json

RUN --mount=type=cache,id=pnpm,target=/pnpm/store \
    pnpm install --frozen-lockfile=false --filter @kinoox/api... --prod=false

# ── Этап 2: сборка ───────────────────────────────────────────
FROM deps AS build

COPY tsconfig.base.json ./
COPY packages/api-client packages/api-client
COPY apps/api apps/api

WORKDIR /repo/apps/api
RUN pnpm exec prisma generate
RUN pnpm exec tsc -p tsconfig.build.json

RUN --mount=type=cache,id=pnpm,target=/pnpm/store \
    pnpm install --frozen-lockfile=false --filter @kinoox/api... --prod

# ── Этап 3: рантайм ──────────────────────────────────────────
FROM node:20-bookworm-slim AS runtime

ENV NODE_ENV=production
ENV TZ=Europe/Moscow

RUN apt-get update \
    && apt-get install -y --no-install-recommends tini ca-certificates \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

COPY --from=build /repo/node_modules ./node_modules
COPY --from=build /repo/apps/api/node_modules ./apps/api/node_modules
COPY --from=build /repo/packages ./packages
COPY --from=build /repo/apps/api/dist ./apps/api/dist
COPY --from=build /repo/apps/api/prisma ./apps/api/prisma
COPY --from=build /repo/apps/api/package.json ./apps/api/package.json

RUN groupadd --system --gid 1001 kinoox \
    && useradd --system --uid 1001 --gid kinoox --create-home kinoox \
    && chown -R kinoox:kinoox /app

USER kinoox

WORKDIR /app/apps/api

# Нет EXPOSE — воркер не слушает HTTP

HEALTHCHECK --interval=30s --timeout=10s --start-period=20s --retries=3 \
    CMD pgrep -f worker.js || exit 1

ENTRYPOINT ["/usr/bin/tini", "--"]

CMD ["node", "--max-old-space-size=4096", "--enable-source-maps", "dist/worker.js"]
```

### 3. `docker/docker-compose.yml` — добавить сервис worker

```yaml
  # ───────────────────────────────────────────────────────────
  #  Worker — фоновая синхронизация каталога (онгоинги + новинки)
  # ───────────────────────────────────────────────────────────
  worker:
    <<: [*restart-policy, *default-logging, *security-hardening]
    build:
      context: ..
      dockerfile: apps/api/Dockerfile.worker
    container_name: kinoox-worker
    stop_grace_period: 30s
    deploy:
      resources:
        limits:
          memory: 4G
        reservations:
          memory: 512M
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
    networks:
      kinoox_backend:
        aliases:
          - worker
    env_file:
      - ../.env
    environment:
      NODE_ENV: production
      TZ: Europe/Moscow
      DATABASE_URL: postgresql://${DB_USER:-kinoox}:${DB_PASSWORD}@postgres:5432/${DB_NAME:-kinoox_db}?schema=public
      REDIS_URL: redis://redis:6379
    ulimits:
      nofile:
        soft: 65536
        hard: 65536
    dns:
      - 8.8.8.8
      - 8.8.4.4
    tmpfs:
      - /tmp:size=128M
    healthcheck:
      test: ["CMD-SHELL", "pgrep -f worker.js || exit 1"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 20s
    labels:
      - "com.centurylinklabs.watchtower.enable=true"
      - "kinoox.service=worker"
      - "kinoox.tier=utility"
```

### 4. `apps/api/src/server.ts` — удалить таймеры

**Удалить** строки 54-93 (все `setTimeout`/`setInterval` для синхронизации).

**Оставить** только:
- Fastify setup
- Socket.io
- Graceful shutdown

### 5. `docker/deploy.sh` — добавить worker

```bash
# Сборка
${DC} build "${BUILD_ARGS[@]}" api web migrate worker

# Ожидание
wait_for worker 30 || warn "Worker не запустился — проверьте логи"
```

## Порядок развёртывания

```bash
# На локалке (git push) → на сервер:

```

```bash
docker compose logs -f worker
docker compose ps
```

## Риски

| Риск | Mitigation |
|------|------------|
| Дублирование синхронизации | Удалить таймеры из API полностью |
| Worker не подключается к БД | `depends_on` + healthcheck |
| Память > 4G | Лимит в docker-compose, мониторинг Grafana |
| Ошибка синхронизации | try/catch + логирование в pino |
