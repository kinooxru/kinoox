Начало работы и работа с эндпоинтами

Catalog Sync API предоставляет доступ к каталогу контента, когда необходимо синхронизировать данные с вашей базой данных. API предоставляет полную и подробную информацию о каждом элементе контента. Это руководство поможет вам разобраться в структуре API и научит использовать его основные функции.

Ссылка на документацию по API: https://catalog-sync-api.rstprgapipt.com/webjars/swagger-ui/index.html

Начало работы
1. Авторизация
API использует аутентификацию с помощью Bearer. При каждом запросе необходимо включать токен авторизации в заголовок:

Authorization: Bearer ваш_токен_авторизации
Токен авторизации необходимо скопировать из списка ваших сайтов на вкладке "Мои сайты" в личном кабинете VeoVeo.

2. Базовый URL
Используется базовый URL для всех запросов:

https://catalog-sync-api.rstprgapipt.com
Используйте этот URL в сочетании с необходимыми эндпоинтами, чтобы получать данные из каталога.

Работа с эндпоинтами
После настройки авторизации и подключения к базовому URL, вы можете использовать следующие эндпоинты для получения информации о контенте из каталога.

1. Получение контента
1.1. Получение подробной информации о контенте для синхронизации
Эндпоинт: POST /v1/contents/details

Описание: Получение полной и подробной информации о контенте для синхронизации с локальной базой данных. Используется, когда необходимо актуализировать данные или получить расширенную информацию о контенте с помощью фильтров.

Тело запроса: Передается JSON-объект с параметрами фильтрации (ContentFilterDto)

Пример:

1) Получение контента за определенный период и по определенному жанру

Запрос:

API: POST /v1/contents/details

Content-Type: application/json

Authorization: Bearer ваш_токен

Пример запроса:

{
  "pagination": {
    "page": 1,
    "pageSize": 20,
    "type": "page"
  },
  "year": [2022],
  "textFilter": "комедия"
}
Ответ: Список объектов ContentDetailDto с метаданными пагинации.

2) Фильтрация и получение контента по нескольким параметрам

Запрос:

API: POST /v1/contents/details

Content-Type: application/json

Authorization: Bearer ваш_токен

Пример запроса:

{
  "pagination": {
    "page": 1,
    "pageSize": 20,
    "type": "page"
  },
  "contentTypeId": [4],
  "genreId": [8],
  "year": [2020, 2021, 2022],
  "countryId": [9]
}
Ответ: Список объектов ContentDetailDto с метаданными пагинации

1.2. Получение облегченной информации о контенте для отображения
Эндпоинт: POST /v1/contents

Описание: Получение упрощенной информации о контенте с использованием фильтров. Используется для быстрого отображения списка контента (например, в пользовательском интерфейсе) без сохранения данных в локальной базе. Возвращает только основную информацию и работает быстрее, чем детальный запрос.

Тело запроса: Передается JSON-объект с параметрами фильтрации (ContentFilterDto)

Пример: Поиск контента по текстовому запросу

Запрос:

API: POST /v1/contents

Content-Type: application/json

Authorization: Bearer ваш_токен

Пример запроса:

{
  "pagination": {
    "page": 1,
    "pageSize": 20,
    "type": "page"
  },
  "textFilter": "звездные войны"
}
Ответ: Список объектов ContentLightDto с метаданными пагинации

1.3. Получение информации о конкретном контенте
Эндпоинт: GET /v1/contents/{id}

Описание: Получение полной информации о контенте по его ID. Используется для отображения или обработки детальной информации о конкретном элементе контента (например, при открытии карточки или страницы с подробностями).

Параметры пути: id - идентификатор контента

Пример: Получение детальной информации о контенте по ID

Запрос: 

API:  GET /v1/contents/834982

Authorization: Bearer ваш_токен  

Ответ: Объект ContentDetailDto, содержащий полную информацию о запрошенном контенте (название, описание, жанры, актёры, метаданные и т.д.).

2. Получение фильтров
— Получение списка годов
Эндпоинт: GET /v1/filters/years

Описание: Возвращает список всех годов, для которых доступен контент в системе. Используется для отображения доступных годов в фильтрах, выпадающих списках или других элементах интерфейса (например, при поиске или навигации по каталогу).

Пример: Получение списка годов

Запрос:

API: GET /v1/filters/years

Content-Type: application/json

Ответ: Массив чисел — список годов, отсортированный по возрастанию или убыванию (в зависимости от реализации).

Пример успешного ответа:

[2018, 2019, 2020, 2021, 2022, 2023, 2024, 2025]
— Получение списка языков
Конечная точка: GET /v1/filters/languages

Описание: Возвращает список всех языков, доступных в системе. Используется для отображения языковых фильтров, настройки интерфейса или локализации — например, при фильтрации контента по аудиодорожке или субтитрам.

Пример: Получение списка языков

Запрос:

API: GET /v1/filters/languages

Content-Type: application/json

Ответ: Массив объектов LanguageDto, содержащих информацию о каждом языке.

Пример успешного ответа:

[
  {
    "id": 1,
    "name": "Русский",
    "slug": "ru"
  },
  {
    "id": 2,
    "name": "Английский",
    "slug": "en"
  },
  {
    "id": 3,
    "name": "Испанский",
    "slug": "es"
  }
]

    "page": число,                     // номер страницы

  },
  "ids": [число, ...],                 // фильтр по ID контента

Обработка ошибок и пагинация

Обработка ошибок
API возвращает стандартные HTTP-коды ответа:

200 — успешный запрос

400 — некорректные параметры запроса

401 — ошибка авторизации

404 — ресурс не найден

500 — внутренняя ошибка сервера

При возникновении ошибки ответ может содержать дополнительную информацию о ее причине.

Пагинация
Все методы получения списков контента поддерживают пагинацию. Для этого в запросе необходимо указать параметры пагинации:

page — номер страницы (начиная с 1)

pageSize — количество элементов на странице

type — тип пагинации (только значение "page")

order — порядок сортировки (ASC или DESC) — в текущей версии не работает, планируется доработка

sortBy — поле для сортировки — в текущей версии не работает, планируется доработка

Примечание: в текущей версии API сортировка всегда происходит по идентификатору контента, независимо от указанных параметров order и sortBy. Функционал сортировки по другим полям будет добавлен в будущих версиях API.

type — тип пагинации (только значение "page")

Ответ содержит метаданные пагинации:

total — общее количество элементов

page — текущая страница

pages — общее количество страниц

hasNextPage — есть ли следующая страница

pageSize — размер страницы

Пример ответа с метаданными пагинации:

{
  "data": [
    // массив объектов ContentDetailDto или ContentLightDto
  ],
  "meta": {
    "page": 1,
    "total": 1250,
    "hasNextPage": true,
    "pageSize": 20,
    "pages": 63
  }
}
