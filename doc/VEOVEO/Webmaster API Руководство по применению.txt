Начало работы и работа с эндпоинтами

Webmaster API предназначен для партнеров, у которых нет собственной базы данных и которые хотят использовать нашу систему в качестве основного источника медиаконтента. Из этого руководства вы узнаете, как устроен API и как использовать его ключевые функции для интеграции и работы с контентом.

Ссылка на документацию по API: https://webmaster-api.rstprgapipt.com/webjars/swagger-ui/index.html

Начало работы
Прежде чем отправлять запросы к API, необходимо выполнить базовые настройки.

1. Авторизация
API использует аутентификацию Bearer.При каждом запросе необходимо включать токен авторизации в заголовок:

Authorization: Bearer ваш_токен_авторизации
Токен авторизации необходимо скопировать из списка ваших сайтов на вкладке «Мои сайты» в личном кабинете VeoVeo.

2. Базовый URL
Базовый URL используется для всех запросов:

https://webmaster-api.rstprgapipt.com
Используйте этот URL в сочетании с необходимыми эндпоинтами, чтобы получать данные из каталога.

Работа с эндпоинтами
После настройки авторизации и подключения к базовому URL вы можете использовать следующие эндпоинты для получения информации о контенте из каталога.

1. Получение контента
Получение упрощенной информации о контенте для отображения
Эндпоинт: POST /v1/contents

Описание: Получение упрощенной информации о контенте с использованием фильтров. Рекомендуется использовать, когда нужно быстро отобразить список контента без сохранения в базе данных — эндпоинт возвращает только основную информацию и работает быстрее.

Тело запроса: JSON-объект с фильтром контента (ContentFilterDto)

Пример: Получение контента по текстовому запросу

Запрос:

API: POST /v1/contents

Content-Type: application/json

Authorization: Bearer ваш_токен

Пример запроса:

{
  "pagination": {
    "page": 2,
    "pageSize": 15,
    "type": "page",
    "order": "DESC",
    "sortBy": "year"
  },
  "contentTypeId": [1, 2],
  "genreId": [3, 7],
  "countryId": [1, 5],
  "languageId": [1],
  "year": [2018, 2019, 2020],
  "ageRestriction": "AGE_16",
  "kinopoiskRating": {
    "from": 7.5,
    "to": 9.0
  },
  "textFilter": "драма"
}
Ответ: Список объектов ContentLightDto с метаданными пагинации

Получение информации о конкретном контенте
Конечная точка: GET /v1/contents/{id}

Описание: Получение подробной информации о контенте по его идентификатору. Используется, когда нужно отобразить или обработать полные данные о конкретном контенте — например, при открытии страницы с подробной информацией.

Параметры пути: id — идентификатор контента

Пример: Получение подробной информации о контенте по идентификатору

Запрос:

API:  GET /v1/contents/12345

Авторизация: Bearer ваш_токен

Ответ: Объект ContentDetailDto, содержащий полную информацию о запрошенном контенте (название, описание, жанры, актеры, метаданные и т. д.).


Получение фильтров

Получение списка годов
Конечная точка: GET /v1/filters/years

: Описание: Возвращает список всех годов, для которых доступен контент в системе. Используется для отображения доступных лет в фильтрах, выпадающих списках или других элементах интерфейса (например, при поиске или навигации по каталогу).

Пример: Получение списка годов

Запрос:

API: GET /v1/filters/years

Content-Type: application/json

Ответ: Массив чисел — список годов, отсортированный по возрастанию или убыванию (в зависимости от реализации).

Пример успешного ответа:

[2018, 2019, 2020, 2021, 2022, 2023, 2024, 2025]
Получение списка языков
Конечная точка: GET /v1/filters/languages

Описание: Возвращает список всех языков, доступных в системе. Используется для отображения языковых фильтров, настройки интерфейса или локализации — например, при фильтрации контента по аудиодорожке или субтитрам.

Пример: Получение списка языков

Запрос:

API: GET /v1/filters/languages

Content-Type: application/json

Ответ: Массив объектов LanguageDto, содержащих информацию о каждом языке.

Пример успешного ответа:

[
  {
    "id": 1,

    "slug": "ru"
  },
  {
    "id": 2,
    "name": "Английский",
    "slug": "en"
  },
  {
    "id": 3,
    "name": "Испанский",
    "slug": "es"
  }
]
Получение списка жанров
Конечная точка: GET /v1/filters/genres

Описание: Возвращает список всех доступных жанров контента. Используется для построения жанровых фильтров в пользовательском интерфейсе — например, при отображении фильмов, сериалов и другого контента по категориям.

Параметры запроса: content-type-id (необязательно) — идентификатор типа контента (например, "movie", "series"). При указании параметра в ответ будут включены только жанры, относящиеся к указанному типу контента.

Пример: Получение списка жанров

Запрос:

API: GET /v1/filters/genres

Content-Type: application/json

Ответ: Массив объектов GenreDto, содержащих информацию о каждом жанре.

Получение списка типов контента

Описание: Возвращает список всех доступных типов контента, таких как фильмы, сериалы, шоу и т. д. Используется для фильтрации, отображения и классификации контента — например, для выбора типа контента при поиске или запросах к API.

Обработка ошибок и пагинация

Обработка ошибок
API возвращает стандартные HTTP-коды ответа:

200 — успешный запрос

400 — некорректные параметры запроса

401 — ошибка авторизации

404 — ресурс не найден

500 — внутренняя ошибка сервера

При возникновении ошибки ответ может содержать дополнительную информацию о ее причине.

Пагинация
Все методы получения списков контента поддерживают пагинацию. Для этого в запросе необходимо указать параметры пагинации:

page — номер страницы (начиная с 1)

pageSize — количество элементов на странице

type — тип пагинации (только значение "page")

order — порядок сортировки (ASC или DESC) — в текущей версии не работает, планируется доработка

sortBy — поле для сортировки — в текущей версии не работает, планируется доработка

Примечание: в текущей версии API сортировка всегда происходит по идентификатору контента, независимо от указанных параметров order и sortBy. Функционал сортировки по другим полям будет добавлен в будущих версиях API.

type — тип пагинации (только значение "page")

Ответ содержит метаданные пагинации:

total — общее количество элементов

page — текущая страница

pages — общее количество страниц

hasNextPage — есть ли следующая страница

pageSize — размер страницы
